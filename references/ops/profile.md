# Profile

The profile is the written contract for a deck. Create it before slides exist and update it when evidence changes.
Template: `assets/templates/profile.md`.

## Facts versus assumptions

Every field is a **fact** (with its source) or an **assumption** (with how it will be checked and by when).

```
Time limit: 5 minutes + 2 minutes Q&A      fact, rules page "Pitch format"
Slide cap: none stated; assume 8            assumption, check with organiser before build
Audience: bank jury, non-technical          fact, organiser email 2026-10-02
```

## Fields

| Field | Why it matters |
|---|---|
| Event and date | picks the mode and the skeleton |
| Audience and decision | tone, jargon level, what the last slide asks for |
| Time limit, Q&A time, speakers | slide count and notes length |
| Rubric with weights | slide allocation and time per slide |
| Format and delivery | PPTX or PDF, screen share or projector, aspect ratio |
| Language | fonts and glyph coverage |
| Brand or template constraints | theme choice |
| Material and sources | what can be claimed; where each number comes from |
| Confidentiality | what may appear on a slide |
| Deadline | scope of polish |

## Variants

- **Event profile**: the table above, plus organiser rules and what the jury scores.
- **Course profile**: marking scheme, word or slide limits, citation style, individual or group work.
- **Talk profile**: venue, session length, audience background, record or no record.

## Open questions

Keep a table `Question | Asked to | Answer | Date`. Ask only what cannot be found in the files. An assumption that
is still open at build time goes into the final report.

## When to update

After the brief is read, when an organiser announces a change, after the first build if the deck reveals missing
evidence, and when a result contradicts an earlier assumption.
