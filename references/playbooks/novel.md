# Playbook: novel

Use when no event mode or playbook fits (a funding update, a lab-meeting talk, a workshop, a client demo).

**Preconditions**: the audience, the time and the desired outcome are known or can be asked in one question.

## Steps

1. **Decompose from first principles** (`ops/framing.md`): decision, evidence, unit of attention, risk, deliverable.
2. **Borrow the closest skeleton**: take the nearest event template from `assets/templates/` and delete what does not apply.
3. **Define success** in one line: "After this the board approves X" or "the class can run Y".
4. **Write the message and the slide list** (`protocol/2-story.md`); title slides as takeaways.
5. **Build and QA** as usual (`protocol/4-build.md`, `protocol/5-qa.md`).
6. **Record the new pattern**: if it will recur, add an event preset and a template (`extending.md`).

## Examples

| Request | Borrowed skeleton | Change |
|---|---|---|
| quarterly project update | datathon | replace findings with milestones and risks |
| client demo | hackathon | demo first; replace roadmap with pricing and next steps |
| workshop opener | research talk | replace the claim with the learning goals |

## Traps

Inventing a structure from scratch when a skeleton fits; skipping the success line.

## Output

Deck source, `.pptx`, `.pdf`, a one-paragraph note on what was borrowed and what was changed.
