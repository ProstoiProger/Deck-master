# Imagery and icons

## What goes on slides

| Asset | Guidance |
|---|---|
| Product screenshots | best evidence; crop to the useful part; synthetic or anonymised data only |
| Diagrams | draw with the layouts (`architecture`, `pipeline`); avoid pasted diagram screenshots |
| Charts | generated from data by `chart_insight`; see `communication/charts-and-tables.md` |
| Photos | only when they carry meaning (the user, the place); otherwise omit |
| Icons | optional; the layouts use numbered badges instead, which need no licence |
| Logos | the organiser's and sponsors' only as permitted by their kit |

## Licences

Keep a source note for every image: where it came from and the licence. Allowed: your own work, public domain,
licences that permit the use (for example CC0 or an open icon set whose terms you checked). Stock sites and template
libraries have their own terms; templates are inspiration for patterns, not assets to copy.

## Trademarks

Brand names, logos, textures and characters of games, companies and products belong to their owners. Do not paste
them to decorate a deck. The `obsidian-craft` and `classic-craft` themes are a generic pixel-block style with original
shapes. Game characters are the one exception, and only on the user's request: they are fetched locally for personal,
non-commercial decks and never redistributed (`design/entities.md`). If an
organiser provides a brand kit, follow it and add a theme file for it (`extending.md`).

## Image files

- Formats: PNG for screenshots and charts, JPEG for photos. Keep each under a few MB.
- Resolution: at least 1600 px wide for a full-width screenshot; the layouts contain the image inside its box and keep its aspect ratio.
- Paths in the deck source are relative to the `.md` file; a missing file is a High finding.
- Put images next to the deck in an `assets/` folder so the project stays portable.

## Alt text

For shared documents add one line in the notes per key image: what it shows and why it matters.
