# Catalog: layouts and themes

Generated by `python scripts/build_catalog.py` from the layout registry and `assets/themes/*.yaml`. Do not edit by hand;
run the script after adding a layout or theme. `python scripts/build_catalog.py --check` fails when this file is stale.

## 1. Layouts

| Layout | Family | Max words | Purpose |
|---|---|---|---|
| `bullets` | content | 70 | Plain titled bullet list with an optional image; the safe fallback layout. |
| `chart_insight` | data | 50 | One chart on the left and the so-what on the right. |
| `comparison` | data | 60 | Table or side-by-side cards comparing our approach with baselines; the winner is highlighted. |
| `kpi` | data | 50 | Two to four headline numbers, each with a label and its context or baseline. |
| `agenda` | frame | 45 | Three to seven numbered steps: what the talk covers or how the work was structured. |
| `closing` | frame | 25 | Closing slide: thanks or questions, where to find the code and the team. |
| `title` | frame | 40 | Opening slide: project name, one-line value proposition, event and team. |
| `advancements` | game | 60 | Advancement tree: milestones as framed icons joined by a path, done, current or locked. |
| `book` | game | 70 | Open book: two parchment pages for what was done and what remains, or any two lists. |
| `boss` | game | 55 | Boss fight: the problem as a boss with a health bar, a portrait and attack patterns. |
| `chat` | game | 70 | Chat window: quotes, feedback or steps as messages from named characters. |
| `crafting` | game | 60 | Crafting table: up to nine ingredients combine into one result. |
| `hud` | game | 50 | Status bars: hearts, hunger, armor and XP as a stats screen for the key numbers. |
| `inventory` | game | 70 | Inventory grid: items as slots with counts, and a legend that names each one. |
| `leaderboard` | game | 50 | Leaderboard: horizontal bars with a character per row; the best one gets the gold. |
| `strata` | game | 60 | Architecture as world layers: sky, grass, dirt, stone, deepslate; components are ores. |
| `trade` | game | 60 | Villager trade list: before on the left, after on the right, with a trader. |
| `team` | people | 50 | Up to six team members with role and one memorable fact. |
| `feature_grid` | story | 70 | Grid of two to six capabilities, each with a short name and one line. |
| `impact` | story | 60 | Two columns: what was achieved and what comes next; use for impact and next steps. |
| `problem` | story | 55 | State the problem in one sentence with one supporting number. |
| `solution` | story | 60 | Show the solution in one line, three benefits and a product visual. |
| `architecture` | tech | 60 | Layered system diagram; the key component is highlighted in the accent color. |
| `demo` | tech | 45 | Screenshot in a browser frame with numbered callouts that walk through the demo. |
| `pipeline` | tech | 55 | Left-to-right pipeline of two to six numbered stages, each with a short caption. |
| `roadmap` | tech | 55 | Horizontal timeline of two to six phases: now, next, later. |
| `tech_stack` | tech | 45 | Technology tiles grouped by layer: language, framework, data, cloud. |

## 2. Layout inputs

### bullets

Accepts: items: bullets; first paragraph becomes a lede; image: picture on the right; or a fenced code block shown in mono on the right

```markdown
# One idea, three supports
- First point
- Second point
- Third point
```

### chart_insight

Accepts: chart: bar | hbar | line | scatter | confusion; table rows `| label | value |` as data, or image: ready chart; takeaway: prop or bullets

```markdown
# Recall rises with every added feature family
layout: chart_insight
chart: bar
source: runs/ablation.csv
takeaway: Time-window features add 6 points of recall.
| Family | Recall |
|---|---|
| Base | 0.71 |
| + windows | 0.77 |
```

### comparison

Accepts: markdown table (header first); `highlight: 2` outlines the 2nd column; use **bold** for the best cell

```markdown
# Ours wins on every metric
layout: comparison
highlight: 3
source: runs/log.jsonl
| Metric | Baseline | Ours |
|---|---|---|
| F1 | 0.81 | **0.92** |
| Latency | 9 s | **2 s** |
```

### kpi

Accepts: items: `92% | F1 score | vs 81% baseline`; first paragraph: takeaway; set `source:` for the numbers

```markdown
# The model beats the baseline by 11 points
layout: kpi
source: runs/log.jsonl#champion
- 92% | F1 | vs 81% baseline
- 2 s | latency | p95
```

### agenda

Accepts: items: one per step, optional `Step | detail`; in game themes `Step | creeper` shows that character in the hotbar slot

```markdown
# What we will cover
layout: agenda
- Problem | who loses and how much
- Solution
- Demo
```

### closing

Accepts: items or paragraphs: contact lines, repo link; props mascot (character name) and achievement (toast text), game themes

```markdown
# Questions?
layout: closing
- github.com/team/project
- team@example.org
```

### title

Accepts: props: eyebrow, subtitle, team, date, mascot (character name, game themes); first paragraph is the subtitle

```markdown
# Team Atlas: fraud alerts in 2 seconds
layout: title
subtitle: Streaming anomaly detection for card payments
team: Atlas | Hackathon 2026
```

### advancements

Accepts: items: `Title | detail | icon or character | done, current or locked` (up to 6)

```markdown
# Three advancements to a pilot
layout: advancements
- Prototype | quests and streaks | sword | done
- Campus pilot | 200 students | diamond | current
- Study | grades against a control group | trophy | locked
```

### book

Accepts: groups: two `## heading` sections with bullets; or items on the left page and the first paragraph on the right

```markdown
# What we did and what we will do
layout: book
## Done
- Prototype with quests and streaks
## Next
- Campus pilot with 200 students
```

### boss

Accepts: props: boss (character name), stat `14 days | what it measures`, hp (0-100); first paragraph: the lore; items: up to 3 attacks

```markdown
# Planners are abandoned within two weeks
layout: boss
boss: zombie
stat: 14 days | median time until students quit a planner
Plans feel like homework about homework.
- No feedback during the week
- Plans are too big to start
```

### chat

Accepts: items: `Speaker | message | character` (up to 7); first paragraph: a [Server] line on top

```markdown
# What students said
layout: chat
A week into the pilot the chat looked like this.
- Dana | the quests made me start | steve
- Mira | the rest token saved my streak | pig
```

### crafting

Accepts: items: ingredients `Name | icon or character`; result: `Name | icon or character | note`; first paragraph: caption

```markdown
# Task + timer + reward = a quest
layout: crafting
result: Quest | sword | the unit of work
- Task | book
- 25 minute timer | torch
- XP reward | xp
```

### hud

Accepts: items: `value | label | heart, hunger, armor, xp or boss | context | fill%` (up to 4); % or `a of b` values fill the bar, or give the fill as a 5th cell

```markdown
# The pilot passed on every stat
layout: hud
source: pilot/results.csv
- 72% | tasks completed | heart | vs 51% with a plain list
- 31 of 40 | kept a 7 day streak | hunger | pilot group
- 4.4 / 5 | would use again | xp | exit survey
```

### inventory

Accepts: items: `Name | detail | icon or character | count` (up to 12); select: slot number to highlight; first paragraph: caption

```markdown
# What is in the backpack
layout: inventory
select: 2
- Quests | tasks in 25 minute steps | sword | 4
- Streaks | daily chain with a rest token | torch | 7
- XP bar | progress you can see | xp | 1
```

### leaderboard

Accepts: items: `Name | value | character | note` (up to 6); better: lower or higher (default higher)

```markdown
# The cache tops the latency board
layout: leaderboard
better: lower
- No cache | 840 ms | zombie
- Plain cache | 410 ms | villager
- Cache + coalescing | 190 ms | steve
```

### strata

Accepts: items: `Layer: component, component` (up to 5 layers); wrap the key component in **bold** to make it a diamond

```markdown
# Four layers keep the alert path short
layout: strata
- Client: Web app, Phone view
- API: Auth, **Quest engine**
- Data: Postgres, Event log
```

### trade

Accepts: items: `Before | After | note` (up to 4); trader: character name (default villager)

```markdown
# Four trades that cut the delay
layout: trade
- 40 minute delay | 2 second alert | streaming scoring
- 11% false alarms | 3% false alarms | alert grouping
```

### team

Accepts: items: `Name | Role | one fact | character` (character is optional: steve, alex, creeper, villager ...)

```markdown
# Four people, one weekend
layout: team
- Aigerim S. | ML engineer | ex-Kaggle grandmaster
- Dana K. | Backend | built the stream layer
```

### feature_grid

Accepts: items: `Name | one-line description`

```markdown
# Four things the app does
layout: feature_grid
- Live scoring | under 2 s per swipe
- Reason codes | top 3 drivers
- Case queue | ranked by loss
- Audit log | every decision
```

### impact

Accepts: groups: `## Achieved` and `## Next` each with bullets

```markdown
# What we shipped and what is next
layout: impact
## Achieved
- Prototype scored 1M events
## Next
- Pilot with one bank branch
```

### problem

Accepts: first paragraph: the statement; props: stat `63% | of projects never ship`, mascot (character name); items: up to 3 evidence bullets

```markdown
# Fraud alerts arrive 40 minutes late
layout: problem
stat: 40 min | median alert delay
source: bank-brief.pdf p.3
Customers lose money before the alert fires.
- 3 of 4 cases are card-not-present
```

### solution

Accepts: first paragraph: the one-line solution; items: up to 3 benefits; image: product picture

```markdown
# Stream scoring cuts alert delay to 2 s
layout: solution
image: assets/ui.png
A streaming model scores each card swipe on arrival.
- 2 s median latency
- Explains every alert
- Runs on one GPU
```

### architecture

Accepts: items: `Layer: component, component`; wrap the key component in **bold**

```markdown
# Events flow through three layers
layout: architecture
- Client: Mobile app, Web
- API: Gateway, **Scoring service**
- Data: Kafka, Feature store
```

### demo

Accepts: image: screenshot path (or `![](path)`); items: up to 4 callouts

```markdown
# Demo: an alert becomes a decision in 3 clicks
layout: demo
image: assets/demo.png
- Alert appears with top reasons
- Analyst opens the case
- Decision is logged
```

### pipeline

Accepts: items: `Stage | caption`; first paragraph: one-line takeaway under the flow

```markdown
# From raw logs to a ranked case list
layout: pipeline
- Ingest | Kafka, 5k events/s
- Features | 42 rolling windows
- Score | LightGBM
- Review | ranked queue
```

### roadmap

Accepts: items: `Phase | milestone | detail`; the first phase is highlighted as current

```markdown
# Three steps to a pilot
layout: roadmap
- Now | Prototype | scored 1M events
- Q1 | Pilot | one branch
- Q3 | Rollout | all branches
```

### tech_stack

Accepts: items: `Layer: Tech, Tech, Tech`

```markdown
# Boring technology, on purpose
layout: tech_stack
- Language: Python, SQL
- ML: LightGBM, scikit-learn
- Data: DuckDB, Parquet
```
